## Reviewed call paths

Multer 2.0.2 is transitive through `apps/api > @nestjs/platform-express@10.4.22`. The API [attachment controller](../../apps/api/src/upload/upload.controller.ts) receives a raw request stream; the [service](../../apps/api/src/upload/upload.service.ts) either handles local bytes or sends the browser to R2. The [avatar controller](../../apps/api/src/user/avatar/avatar.controller.ts) uses its own [stream transport](../../apps/api/src/user/avatar/avatar-transport.ts). [Bootstrap](../../apps/api/src/main.ts) disables Nest's default body parser and installs JSON/form parsing for other routes. No application route calls Multer or Nest's Multer interceptors (`FileInterceptor`, `FilesInterceptor`, `AnyFilesInterceptor`, `FileFieldsInterceptor`, `NoFilesInterceptor`) or `MulterModule`. The installed Nest platform package calls Multer from those interceptor classes, rather than for every Express request. Thus the six Multer advisories have **no demonstrated parser entry from the reviewed routes**. This does not prove a different running image or a future fork has no such entry.

The API declares `nanoid@3.3.14` directly, but no API source or script calls it; attachment IDs use `crypto.randomUUID()`. The affected nanoid functions require a negative or zero generator size. ESLint tool paths under `packages/config-eslint` include `minimatch > brace-expansion` and `eslint > js-yaml`; no reviewed server route sends user data into these functions. The Web path to Browserslist is `apps/web > next@16.3.3 > styled-jsx > @babel/core > @babel/helper-compilation-targets > browserslist > update-browserslist-db > browserslist`. No reviewed route supplies dynamic Browserslist queries or stats. No source `browserslist-stats.json` was found outside installed dependencies. Build workers can still process untrusted source, YAML, glob patterns, or stats files if an operator permits that input.

Both Docker builds install all workspaces. The [API Dockerfile](../../apps/api/Dockerfile) copies the root pnpm store and packages into the runner; the [Web Dockerfile](../../apps/web/Dockerfile) copies a Next standalone output. This triage did not rebuild or inspect a fresh artifact, so runtime package presence and actual VPS state remain unverified. Authentication, proxy rules, and rate limits were not credited as mitigations for any advisory condition.
